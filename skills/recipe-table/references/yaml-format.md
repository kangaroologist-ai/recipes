# 食谱 YAML 格式

## 顶层字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | 是 | 菜名 |
| `servings` | 否 | 做出几份，默认 1。大于 1 时营养表多一列“整份” |
| `serving_name` | 否 | 份的量词，默认“份”，比如“片”会显示成“每片” |
| `ingredients` | 是 | 材料，key 是简短英文 id |
| `steps` | 是 | 步骤，key 是简短英文 id，按做菜顺序写 |

## 材料

```yaml
egg: {name: 鸡蛋, qty: 1, unit: 个, note: 室温, nut: [78, 6, 1, 5, 0, 62], src: "USDA#01129"}
```

| 字段 | 说明 |
|---|---|
| `name` | 通用名称，不写品牌 |
| `qty` / `unit` | 用量，尽量用 g / ml；做不到就保留原单位（个、撮、tsp、片） |
| `note` | 可选，显示在名称下面的小字，比如“约 125 g”“室温” |
| `nut` | 这份用量对应的 `[热量 kcal, 蛋白质 g, 碳水 g, 脂肪 g, 膳食纤维 g, 钠 mg]`，不是每 100 g |
| `src` | 营养数据来源，只留在 YAML 里，不显示 |

## 步骤

```yaml
wet:  {action: 打散, in: [egg, milk], min: 1}
rest: {action: 静置, in: [mix], min: 7, passive: true}
heat: {phase: heat, action: 热锅, note: 小火 · 抹黄油, in: [butter], min: 3, passive: true, end_with: rest}
fry:  {phase: heat, action: 煎, note: 小火 · 加盖, in: [rest, heat], min: 2}
```

| 字段 | 说明 |
|---|---|
| `action` | 只写一个动词（拌匀、静置、煎、翻面 / Whisk, Rest, Cook, Flip）。做的是什么从左边的材料就看得出来，不用重复 |
| `note` | 可选，动词下面的小字，放火候、程度这类关键提示，用 `·` 分隔，每段一行，比如 `小火 · 加盖`、`无干粉即停` |
| `in` | 用到的材料 id 或前面步骤的 id，决定配方表的合并格 |
| `min` | 时长（分钟） |
| `passive` | `true` 表示不用一直动手（静置、浸泡、热锅、烤箱里烤），可以和别的步骤同时进行，格子里标“等待” |
| `phase` | `prep`（备料/混合，默认）、`wait`（写了 `passive` 时自动）、`heat`（开火的步骤，要手动写）。只影响图片版颜色 |
| `after` | 只影响时间线：等这些步骤结束才开始，不进配方表（很少用，见规则 4） |
| `end_with` | 和某一步同时结束（预热最常用：静置结束时锅刚好热）。只能用在 `passive` 步骤上 |
| `start_with` | 和某一步同时开始。只能用在 `passive` 步骤上 |

## 规则

脚本会检查前四条，出错时报出具体的 id：

1. 整张表只能有一个终点步骤，也就是没有被别的步骤 `in` 用到的那一步。
2. 每个材料都必须被用到，而且只能用一次。同一种材料分两次加入时拆成两个，比如 `milk1: {name: 牛奶（一半）}` 和 `milk2`，营养数据也按比例拆开。
3. `phase` 只能是 `prep` / `wait` / `heat`；`nut` 必须是 6 个数。
4. 步骤按做菜顺序写：每一步要排在它 `in` / `after` / `end_with` 用到的步骤后面。
5. 准备工作（热锅、化黄油、预热烤箱、烧水）要进配方表，因为看表的人得知道有这一步、什么时候做：
   - 用到材料的（热锅抹油、化黄油）就把那个材料写进 `in`，再把这一步写进用它的步骤的 `in`，比如 `butter → 热锅抹黄油 → 煎`。
   - 不用材料的（预热烤箱、烧水）`in` 留空，但同样写进用它的步骤的 `in`；表里会单独占一行，从最左边拉到用它的那一步。
   - 一般标 `passive: true`、`phase: heat`，再用 `end_with` 对齐到它在等的那一步，表格里它会排在那一步正下方。
   - `after` 只留给确实不该进表的依赖。

## 时间线怎么排

默认一个人做饭：不是 `passive` 的步骤一个接一个按列出顺序做，不会重叠；`passive` 步骤（静置、浸泡、热锅、烤）可以和动手的步骤同时进行。所以配方表上能并行的两支（比如拌干料和打湿料），在时间线上会排成先后。写完看一眼时间线是否符合实际：

- 两件需要手的事不会同时出现；同时出现说明有一步该是 `passive` 却没标，或者标错了。
- 热锅、预热这类步骤结束的时刻，正好是要用它的那一步开始的时刻。
- 时长合理：比如 10 g 黄油在热锅里 30 秒就化，“化黄油 2 分钟”其实是热锅的时间，步骤名要写清楚是“热锅化黄油”。

## 英文版字段

导出英文图片（`--table-png --en`）时用，写 YAML 时顺手一起填：

| 位置 | 字段 |
|---|---|
| 顶层 | `title_en`；有 `serving_name` 时加 `serving_name_en`（复数，如 `slices`），没有时默认 `serving` |
| 材料 | `name_en`；有 `note` 时加 `note_en`；单位不是 g/ml/tsp 这类通用单位时可加 `unit_en`（个 → 空，撮 → pinch，片 → slices 已内置） |
| 步骤 | `action_en`；有 `note` 时加 `note_en`，含 `·` 或逗号时加引号，比如 `note_en: "low · covered"` |

英文名同样不写品牌，用英文菜谱里的常用叫法（比如 0 脂希腊酸奶是 Nonfat Greek yogurt）。动作用一个常见的烹饪动词：Whisk、Stir、Rest、Soak、Preheat、Cook / Fry、Flip。注意词义：fold 是把打发的东西轻轻翻进去，普通拌匀不要用。

## 营养计算

- 营养表的每份值 = 所有 `nut` 相加 ÷ `servings`，四舍五入保留一位小数。
- “整份”列 = 显示出来的每份值 × 份数，所以两列总能乘得上（和按原始总和算可能差 0.1）。
- 代糖（阿洛酮糖、赤藓糖醇等）按 0 kcal 计；盐、泡打粉这类小量材料也要填钠。
